# NFC 통합관리 플랫폼 전환 제안서 (v0.1)

> 상태: 초안 · 합의 후 v0.2  
> 대상: Link-U(wow-linku.co.kr) 기반 Pet-NFC Connect 코드베이스  
> 관련 Canvas: Cursor 사이드 패널 `nfc-platform-proposal.canvas.tsx`

---

## 1. 배경과 목표

### 현재
- 대외 브랜드 **Link-U**는 NFC로 발견자↔보호자를 앱 없이 연결하는 **안심·위치** 플랫폼으로 포지셔닝됨.
- 홈(`/`)은 5모드(펫/메모리/키즈/러기지/골드) + 링크유-동행 타일 게이트.
- 태그 UID 해석(`/t/[tag_id]`), 대시보드, 관리자 인벤토리, Shop, Wayfinder, Android Writer/BLE가 이미 운영·개발됨.

### 목표
1. **NFC 통합관리 시스템**으로 사이트를 확장한다.
2. **Link-U 위치·안심**은 플랫폼의 **한 섹션**으로 둔다.
3. **다양한 NFC 방식**(안심 연결, 범용 NDEF 도구, 기업·시설, 향후 수직 영역)을 섹션으로 추가할 수 있게 한다.
4. **소비자가 NFC 태그 외형을 직접 디자인**하고, **3D 프리뷰·3D 프린팅 출력·주문**까지 이어지게 한다.
5. **메인 랜딩페이지를 신규 구현**하여 위 구조를 한눈에 전달한다.

### 비목표 (이번 전환에서 하지 않음)
- DB 테이블명(`pets` 등) 일괄 rename
- iOS 네이티브 전면 개발
- 기존 `/t/[uid]`·모드 대시보드 기능 폐기

## 3. 정보 구조 (IA)

```
/                         ← 신규 플랫폼 랜딩
├── /linku 또는 /solutions/safety
│     ├── /pet|/elder|/child|/luggage|/gold   (기존 유지)
│     ├── /dashboard/[kind] …                 (기존 유지)
│     └── /wayfinder …                        (동행, 기존 유지)
├── /design 또는 /studio                      ← 태그 디자인 (신규)
│     ├── 폼팩터 선택 → 2D 에디터 → 3D 프리뷰
│     └── 주문 체크아웃 → Shop 연동
├── /tools                                    ← 범용 NFC 도구 (신규/확장)
├── /business                                 ← 기업·시설 (테넌트·동행 확장)
├── /shop                                     (기존, 디자인 SKU 확장)
├── /hub|/admin|/t/[uid]|/install             (기존 유지)
└── /manual|/legal …                          (기존 유지)
```

**원칙:** 딥링크·SEO·이미 배포된 태그 URL(`/t/...`, 모드 경로)은 **깨지 않는다**. 홈과 내비만 재구성한다.

## 6. 태그 디자인 · 3D · 출력

### 사용자 플로우
1. **폼팩터 선택** — 펜던트, 키링, 카드, 플레이트 등 (초기 2–3종)
2. **표면 디자인** — 텍스트, 로고, 색, 패턴 (2D 에디터)
3. **3D 프리뷰** — 칩 슬롯·두께·스케일 확인
4. **기능 바인딩** — Link-U 모드 / 단순 URL / 수령 후 활성화
5. **주문·출고** — UID 예약 → 프린트 큐 → 배송 → 활성화

### 데이터 (안)
- `form_factors` — 치수, 인쇄 가능 영역, 템플릿 glTF/STL 키
- `tag_designs` — 유저 디자인 JSON, 썸네일 R2 키, user_id
- `print_jobs` — design_id, order_id, status(queued/printing/qa/shipped)
- `shop_orders.design_id` — 기존 주문과 연결

### 기술
| 층 | 제안 |
|---|---|
| 2D | Canvas/SVG 에디터 |
| 3D | glTF + three.js / R3F (클라이언트 전용, Edge 번들 분리) |
| 저장 | D1 메타 + R2 에셋 |
| 출력 | STL/3MF export → Admin 큐 → WOW3D 공정(자가/시트/API) |

### 단계적 출시
- **MVP (P3):** 2D + 정적/간단 회전 목업 + 주문
- **P4:** 실시간 3D 텍스처 프리뷰
- **P5:** 출력 파일·프린트 큐·공정 연동

## 7. 로드맵

| Phase | 이름 | 기간(추정) | 산출물 |
|---|---|---|---|
| **P0** | 기반 정리 | 2–3주 | 용어집, 라우트 맵, SEO 키워드, 확장 포인트 문서 |
| **P1** | 신규 랜딩 | 2–3주 | `/` 재구성, 섹션 허브, 기존 홈 → `/linku` 이동 |
| **P2** | Link-U 섹션화 | 2주 | 내비/허브에서 하위 제품화, 카피 정리 |
| **P3** | 디자인 MVP | 4–6주 | 폼팩터·2D 에디터·주문·design 저장 |
| **P4** | 3D 프리뷰 | 4–6주 | glTF 뷰어, 텍스처 매핑, 모바일 성능 |
| **P5** | 출력 파이프라인 | 3–5주 | export, Admin 큐, WOW3D 연동, 배송 |

총 캘린더: 병렬 가능 시 **약 4–6개월**, 순차 시 더 김. P4–P5는 출력 운영 방식에 따라 ±50%.

## 8. 결정 필요 사항 (v0.2 입력)

1. **브랜드:** 플랫폼 대외명을 Link-U로 유지할지, 상위 브랜드를 신설할지  
2. **출력 운영:** WOW3D 자가 출력 vs 외주 / 검수 SLA·반품  
3. **초기 SKU:** 폼팩터 수, 칩(NTAG213/215 등), 인쇄 가능 영역 스펙  
4. **우선 시장:** B2C 커스텀 태그 선진입 vs B2B 시설 NFC 선진입  
   - 기본 제안: **B2C 디자인 + 기존 Link-U 병행**
